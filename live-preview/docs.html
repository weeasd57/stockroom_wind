Welcome to TradingHub Pro

TradingHub Pro is a comprehensive social trading platform that enables traders to share insights, connect with investors, and monetize their expertise through premium subscriptions.

Version 1.0.0 - This documentation covers the complete setup and usage of TradingHub Pro.

Key Features

  • Social Trading Posts - Share trading ideas with rich content
  • Premium Subscriptions - Monetize expertise with Pro and Broker plans
  • Telegram Integration - Broadcast signals to followers
  • Real-time Analytics - Track performance and engagement
  • PayPal Payments - Secure payment processing
  • Dark/Light Theme - Beautiful UI with theme support

Application Overview

This section gives a high-level overview of the main areas of TradingHub Pro and how they fit together for both regular users and administrators.

User-facing Pages

  • Home / Feed (/) – Global trading feed showing public posts with filters and sorting.
  • Login / Signup (/login) – Email/password and OAuth authentication (plus demo user login).
  • Traders Directory (/traders) – Discover traders, view stats and follow/unfollow.

Admin Panel

  • Dashboard (/admin/dashboard) – Overview of key metrics and platform health.
  • Users Management (/admin/users) – View, activate/deactivate, ban and delete users.
  • Posts Moderation (/admin/posts) – Approve, reject, feature and delete posts.

Integrations & Services

  • Supabase – Authentication, profiles, posts, and analytics storage.
  • PayPal – Subscription and payments integration for Pro / Broker plans.
  • Telegram Bot – Optional integration to broadcast trading signals.
  • Theming – Dark/Light mode with CSS variables shared across app and admin.

Trading Posts

Trading posts are the core content of TradingHub Pro. Traders can publish ideas with symbols, entry/target/stop prices, sentiment, and rich analysis. Posts appear in the global feed, traders directory, and profile pages.

  • Create posts from the home/profile pages using the Create Post dialog.
  • Each post tracks price history, target/stop status, and performance metrics.
  • Posts can be public or premium-only depending on the author subscription.

Subscriptions

Subscriptions allow traders to monetize their content. Users can subscribe to premium plans (for example Pro or Broker plans) using PayPal, unlocking premium posts and additional limits.

  • Pricing and plans are exposed via the pricing page and subscription APIs.
  • Subscription state is cached in the app and checked before accessing premium content.
  • PayPal webhooks are used to keep subscription status in sync with payments.

Telegram Integration

TradingHub Pro can broadcast trading signals to Telegram using a dedicated bot. Traders configure their bot token and channel settings from the profile Telegram tab.

  • Enable Telegram by providing TELEGRAMBOT_TOKEN and related env variables.
  • When enabled, new posts or signals can be pushed automatically to Telegram channels.
  • The integration is optional and can be disabled without affecting the core app.

Payment System (PayPal)

The payment system is built on top of PayPal REST APIs. It powers recurring subscriptions and one-time payments depending on your configuration.

  • Uses NEXT_PUBLIC_PAYPAL_CLIENT_ID and PAYPAL_CLIENT_SECRET from .env.local.
  • Supports sandbox and live modes via the PAYPAL_MODE variable.
  • Includes a diagnostic script scripts/test-paypal-credentials.js to verify credentials.
Note: Always use sandbox credentials for testing and switch to live credentials only in production environments.

Posts API

The Posts API is used by the frontend to list, create and fetch individual trading posts. In a typical setup you will interact with it indirectly through the application UI, but you can also call the endpoints from your own backend scripts or integrations.

Common Endpoints

GET    /api/posts           # List posts (supports query filters)
GET    /api/posts/[id]     # Fetch a single post by id (public data)
POST   /api/posts          # Create a new post (requires authenticated user)
PATCH  /api/posts/[id]     # Update a post (owner or admin only)
DELETE /api/posts/[id]     # Delete a post (owner or admin only)
Note: Exact routes and payloads may change between versions. Always check the implemented handlers under src/app/api in your copy of the source code.

Users API

The Users API exposes basic read operations for user profiles and is primarily used by the traders directory, profile pages and admin tools.

Common Endpoints

GET  /api/users            # List users (supports pagination and filters)
GET  /api/users/[id]      # Fetch a single user profile
PATCH /api/users/[id]     # Update profile (owner) or perform admin actions
Security: Write operations should always be protected by authentication and role checks. Never expose raw user data to the public without proper filtering.

Webhooks

Webhooks are used to receive asynchronous events from external services such as PayPal. They keep subscription and payment state in sync with TradingHub Pro.

PayPal Webhook

Configure a webhook URL in your PayPal developer dashboard that points to your deployment, for example: 

POST https://your-domain.com/api/webhooks/paypal

The handler should verify the event signature, then update subscription status in your database based on the incoming event type (created, renewed, cancelled, etc.).

Deploy to VPS

You can deploy TradingHub Pro to any modern Linux VPS (for example Ubuntu 22.04) that supports Node.js. The exact steps depend on your provider, but the general flow is:

  1. Provision a VPS and point your domain DNS to its IP address.
  2. Install Node.js LTS, Git and a process manager such as pm2.
  3. Clone your TradingHub Pro repository to the server.
  4. Create an .env.local file on the VPS with the same values you use locally.
  5. Run npm install, then npm run build and finally npm run start (or use pm2 start).
  6. Configure a reverse proxy such as Nginx or Caddy to serve the app over HTTPS.
Tip: Use separate environments (staging vs production) with different databases and API keys to keep test data isolated from real traders.

Docker Setup

Telegram Webhook Diagnostic Script

Checks and fixes Telegram webhook configuration. Also validates endpoint reachability and prints bot info. Usage: node scripts/check-telegram-webhook.js 

/**
 * Telegram Webhook Diagnostic Script
 * Checks and fixes webhook configuration
 * 
 * Usage: node scripts/check-telegram-webhook.js
 */
const fs = require('fs');
const path = require('path');
const https = require('https');

function httpRequest(url, options = {}) {
  return new Promise((resolve, reject) => {
    const req = https.request(url, {
      method: options.method || 'GET',
      headers: options.headers || {}
    }, (res) => {
      let data = '';
      res.on('data', chunk => data += chunk);
      res.on('end', () => {
        try {
          resolve({ status: res.statusCode, json: () => JSON.parse(data) });
        } catch {
          resolve({ status: res.statusCode, json: () => ({}) });
        }
      });
    });
    req.on('error', reject);
    if (options.body) req.write(typeof options.body === 'string' ? options.body : JSON.stringify(options.body));
    req.end();
  });
}

Telegram Domain Setup Script

Sets Telegram webhook to your public domain (or tunnel) and verifies configuration. Usage: npm run telegram:setup or node scripts/setup-telegram-domain.js 

#!/usr/bin/env node

/**
 * Telegram Domain Setup Script
 * npm run telegram:setup
 * Sets up Telegram bot webhook with domain configuration
 */

const https = require('https');
const { URL } = require('url');
const path = require('path');
const fs = require('fs');

// Load environment variables from .env.local
function loadEnvFile() {
  const envPath = path.join(__dirname, '..', '.env.local');
  if (fs.existsSync(envPath)) {
    const envContent = fs.readFileSync(envPath, 'utf8');
    const lines = envContent.split('\n');
    
    lines.forEach(line => {
      line = line.trim();
      if (line && !line.startsWith('#')) {
        const [key, ...valueParts] = line.split('=');
        if (key && valueParts.length > 0) {
          const value = valueParts.join('=');
          process.env[key] = value;
        }
      }
    });
    console.log('✅ Loaded environment variables from .env.local');
  } else {
    console.log('⚠️ No .env.local file found');
  }
}

// Load env file first
loadEnvFile();

// Configuration
const config = {
  botToken: process.env.TELEGRAM_BOT_TOKEN || process.env.TELEGRAMBOT_TOKEN,
  domain: process.env.NEXT_PUBLIC_APP_URL || process.argv[2],
  webhookSecret: process.env.TELEGRAM_WEBHOOK_SECRET,
};

// Colors for console output
const colors = {
  red: '\x1b[31m',
  green: '\x1b[32m',
  yellow: '\x1b[33m',
  blue: '\x1b[34m',
  reset: '\x1b[0m'
};

function log(message, color = colors.reset) {
  console.log(`${color}${message}${colors.reset}`);
}

// Validate inputs
function validateConfig() {
  if (!config.botToken) {
    log('❌ Bot Token is required', colors.red);
    log('Set TELEGRAM_BOT_TOKEN or TELEGRAMBOT_TOKEN in .env.local', colors.yellow);
    process.exit(1);
  }

  if (!config.domain) {
    log('❌ Domain is required', colors.red);
    log('Usage: node setup-telegram-domain.js https://yourdomain.com', colors.yellow);
    log('Or set NEXT_PUBLIC_APP_URL in .env.local', colors.yellow);
    process.exit(1);
  }

  // Ensure domain has https://
  if (!config.domain.startsWith('http')) {
    config.domain = `https://${config.domain}`;
  }

  try {
    new URL(config.domain);
  } catch (error) {
    log('❌ Invalid domain URL', colors.red);
    process.exit(1);
  }

  log('✅ Configuration validated', colors.green);
}

// Make HTTPS request
function makeRequest(url, data = null) {
  return new Promise((resolve, reject) => {
    const urlObj = new URL(url);
    const options = {
      hostname: urlObj.hostname,
      port: urlObj.port || 443,
      path: urlObj.pathname + urlObj.search,
      method: data ? 'POST' : 'GET',
      headers: {
        'Content-Type': 'application/json',
        'User-Agent': 'Telegram-Domain-Setup-Script'
      }
    };

    if (data) {
      const postData = JSON.stringify(data);
      options.headers['Content-Length'] = Buffer.byteLength(postData);
    }

    const req = https.request(options, (res) => {
      let responseData = '';
      res.on('data', (chunk) => {
        responseData += chunk;
      });
      res.on('end', () => {
        try {
          const parsedData = JSON.parse(responseData);
          resolve(parsedData);
        } catch (error) {
          reject(new Error(`Invalid JSON response: ${responseData}`));
        }
      });
    });

    req.on('error', (error) => {
      reject(error);
    });

    if (data) {
      req.write(JSON.stringify(data));
    }

    req.end();
  });
}

PayPal Credentials Diagnostic Script

Verifies your PayPal REST API credentials (sandbox or live) by fetching an access token. Usage: node scripts/test-paypal-credentials.js 

/**
 * PayPal Credentials Diagnostic Script
 * Tests if PayPal credentials are valid and can authenticate
 */
const fs = require('fs');
const path = require('path');

// Load .env.local manually
try {
  const envPath = path.join(__dirname, '..', '.env.local');
  const envContent = fs.readFileSync(envPath, 'utf8');
  envContent.split('\n').forEach(line => {
    const trimmed = line.trim();
    if (trimmed && !trimmed.startsWith('#')) {
      const [key, ...valueParts] = trimmed.split('=');
      if (key && valueParts.length > 0) {
        let value = valueParts.join('=').trim();
        // Strip wrapping quotes like KEY="value" to behave like dotenv
        if ((value.startsWith('"') && value.endsWith('"')) || (value.startsWith('\'') && value.endsWith('\''))) {
          value = value.slice(1, -1);
        }
        process.env[key.trim()] = value;
      }
    }
  });
} catch (err) {
  console.error('Could not load .env.local:', err.message);
}

const PAYPAL_MODE = ((process.env.PAYPAL_MODE || process.env.NEXT_PUBLIC_PAYPAL_MODE || 'sandbox').toLowerCase() === 'live') ? 'live' : 'sandbox';
const PAYPAL_BASE = PAYPAL_MODE === 'live'
  ? 'https://api-m.paypal.com'
  : 'https://api-m.sandbox.paypal.com';

function getCredentials() {
  const isLive = PAYPAL_MODE === 'live';
  const clientId = isLive
    ? (process.env.PAYPAL_LIVE_CLIENT_ID || process.env.NEXT_PUBLIC_PAYPAL_CLIENT_ID_LIVE || process.env.PAYPAL_CLIENT_ID || process.env.NEXT_PUBLIC_PAYPAL_CLIENT_ID)
    : (process.env.PAYPAL_SANDBOX_CLIENT_ID || process.env.NEXT_PUBLIC_PAYPAL_CLIENT_ID_SANDBOX || process.env.PAYPAL_CLIENT_ID || process.env.NEXT_PUBLIC_PAYPAL_CLIENT_ID);
  const clientSecret = isLive
    ? (process.env.PAYPAL_LIVE_CLIENT_SECRET || process.env.PAYPAL_CLIENT_SECRET)
    : (process.env.PAYPAL_SANDBOX_CLIENT_SECRET || process.env.PAYPAL_CLIENT_SECRET);
  return { clientId, clientSecret };
}

async function testPayPalAuth() {
  console.log('🔍 Testing PayPal Credentials...\n');
  
  const { clientId, clientSecret } = getCredentials();
  
  console.log('📋 Configuration:');
  console.log(`   Mode: ${PAYPAL_MODE}`);
  console.log(`   Base URL: ${PAYPAL_BASE}`);
  console.log(`   Client ID: ${clientId ? `${clientId.substring(0, 20)}...` : '❌ MISSING'}`);
  console.log(`   Client Secret: ${clientSecret ? `${clientSecret.substring(0, 10)}...` : '❌ MISSING'}\n`);
  
  if (!clientId || !clientSecret) {
    console.error('❌ ERROR: Missing credentials!');
    console.log('\n📝 Please set the following in .env.local:');
    console.log('   NEXT_PUBLIC_PAYPAL_CLIENT_ID=');
    console.log('   PAYPAL_CLIENT_SECRET=');
    console.log('   PAYPAL_MODE=sandbox\n');
    process.exit(1);
  }
  
  console.log('🔐 Attempting to authenticate with PayPal...\n');
  
  const auth = Buffer.from(`${clientId}:${clientSecret}`).toString('base64');
  
  try {
    const response = await fetch(`${PAYPAL_BASE}/v1/oauth2/token`, {
      method: 'POST',
      headers: {
        'Authorization': `Basic ${auth}`,
        'Content-Type': 'application/x-www-form-urlencoded',
      },
      body: 'grant_type=client_credentials',
    });
    
    const responseText = await response.text();
    
    if (!response.ok) {
      console.error('❌ AUTHENTICATION FAILED!\n');
      console.log('HTTP Status:', response.status, response.statusText);
      
      try {
        const errorData = JSON.parse(responseText);
        console.log('Error Response:', JSON.stringify(errorData, null, 2));
        
        if (response.status === 401) {
          console.log('\n💡 Solution:');
          console.log('   1. Your Client ID or Secret is incorrect');
          console.log('   2. Get new credentials from PayPal Dashboard:');
          console.log('      👉 https://developer.paypal.com/dashboard/');
          console.log('   3. Make sure you are in Sandbox mode');
          console.log('   4. Copy both Client ID and Secret from the SAME app');
          console.log('   5. Update .env.local with the new credentials');
          console.log('   6. Restart your dev server\n');
          
          console.log('📖 Full guide: PAYPAL_CREDENTIALS_SETUP.md\n');
        }
      } catch (e) {
        console.log('Raw Error:', responseText);
      }
      
      process.exit(1);
    }
    
    const data = JSON.parse(responseText);
    
    console.log('✅ AUTHENTICATION SUCCESSFUL!\n');
    console.log('Access Token:', data.access_token.substring(0, 30) + '...');
    console.log('Token Type:', data.token_type);
    console.log('Expires In:', data.expires_in, 'seconds');
    console.log('App ID:', data.app_id || 'N/A');
    console.log('\n🎉 Your PayPal credentials are working correctly!');
    console.log('✅ You can now use PayPal checkout in your app.\n');
    
  } catch (error) {
    console.error('❌ NETWORK ERROR:', error.message);
    console.log('\n💡 Possible causes:');
    console.log('   - No internet connection');
    console.log('   - PayPal API is down');
    console.log('   - Firewall blocking the request\n');
    process.exit(1);
  }
}
