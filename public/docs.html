Welcome to Sharks Zone

Sharks Zone is a comprehensive social trading platform that enables traders to share insights, connect with investors, and monetize their expertise through premium subscriptions.

Version 1.0.0 - This documentation covers the complete setup and usage of Sharks Zone.

Key Features

  • Social Trading Posts - Share trading ideas with rich content
  • Premium Subscriptions - Monetize expertise with Pro and Broker plans
  • Telegram Integration - Broadcast signals to followers
  • Real-time Analytics - Track performance and engagement
  • PayPal Payments - Secure payment processing
  • Dark/Light Theme - Beautiful UI with theme support

Trading Posts

Trading posts are the core content of Sharks Zone. Traders can publish ideas with symbols, entry/target/stop prices, sentiment, and rich analysis. Posts appear in the global feed, traders directory, and profile pages.

  • Create posts from the home/profile pages using the Create Post dialog.
  • Each post tracks price history, target/stop status, and performance metrics.
  • Posts can be public or premium-only depending on the author subscription.

Subscriptions

Subscriptions allow traders to monetize their content. Users can subscribe to premium plans (for example Pro or Broker plans) using PayPal, unlocking premium posts and additional limits.

  • Pricing and plans are exposed via the pricing page and subscription APIs.
  • Subscription state is cached in the app and checked before accessing premium content.
  • PayPal webhooks are used to keep subscription status in sync with payments.

Telegram Integration

Sharks Zone can broadcast trading signals to Telegram using a dedicated bot. Traders configure their bot token and channel settings from the profile Telegram tab.

  • Enable Telegram by providing TELEGRAMBOT_TOKEN and related env variables.
  • When enabled, new posts or signals can be pushed automatically to Telegram channels.
  • The integration is optional and can be disabled without affecting the core app.

Payment System (PayPal)

The payment system is built on top of PayPal REST APIs. It powers recurring subscriptions and one-time payments depending on your configuration.

  • Uses NEXT_PUBLIC_PAYPAL_CLIENT_ID and PAYPAL_CLIENT_SECRET from .env.local.
  • Supports sandbox and live modes via the PAYPAL_MODE variable.
  • Includes a diagnostic script scripts/test-paypal-credentials.js to verify credentials.
Note: Always use sandbox credentials for testing and switch to live credentials only in production environments.

🔐 PayPal Login for Premium Brokers

Enable automatic premium plan activation for brokers when they connect their PayPal account. This feature allows brokers to verify their identity through PayPal OAuth and automatically enables their premium broker plan without manual approval.

How It Works

  1. Broker navigates to Profile → Premium Plan tab
  2. Clicks "Connect with PayPal" button
  3. Redirects to PayPal OAuth authorization page
  4. Broker logs in and approves permissions
  5. System verifies PayPal account and saves credentials
  6. Premium Plan is automatically activated ✅
  7. Broker can now accept subscriptions from users

Implementation

API Route: PayPal OAuth Login

File: src/app/api/auth/paypal/login/route.js

import { NextResponse } from 'next/server';

export async function GET(request) {
  const clientId = process.env.NEXT_PUBLIC_PAYPAL_CLIENT_ID;
  const redirectUri = process.env.NEXT_PUBLIC_PAYPAL_REDIRECT_URI;
  const scope = 'openid profile email';
  
  const paypalAuthUrl = `https://www.${process.env.PAYPAL_MODE === 'live' ? '' : 'sandbox.'}paypal.com/connect/?` +
    `flowEntry=static&` +
    `client_id=${clientId}&` +
    `scope=${encodeURIComponent(scope)}&` +
    `redirect_uri=${encodeURIComponent(redirectUri)}&` +
    `response_type=code`;

  return NextResponse.redirect(paypalAuthUrl);
}

API Route: PayPal Callback Handler

File: src/app/api/auth/paypal/callback/route.js

import { NextResponse } from 'next/server';
import { createClient } from '@/utils/supabase/server';

export async function GET(request) {
  const searchParams = request.nextUrl.searchParams;
  const code = searchParams.get('code');
  
  if (!code) {
    return NextResponse.redirect(
      new URL('/login?error=paypal_auth_failed', request.url)
    );
  }

  try {
    // 1. Get Access Token from PayPal
    const tokenResponse = await fetch(
      `${process.env.PAYPAL_OAUTH_URL}/v1/oauth2/token`,
      {
        method: 'POST',
        headers: {
          'Content-Type': 'application/x-www-form-urlencoded',
          'Authorization': `Basic ${Buffer.from(
            `${process.env.NEXT_PUBLIC_PAYPAL_CLIENT_ID}:${process.env.PAYPAL_CLIENT_SECRET}`
          ).toString('base64')}`
        },
        body: new URLSearchParams({
          grant_type: 'authorization_code',
          code: code
        })
      }
    );

    const tokenData = await tokenResponse.json();
    const accessToken = tokenData.access_token;

    // 2. Get User Info from PayPal
    const userInfoResponse = await fetch(
      `${process.env.PAYPAL_OAUTH_URL}/v1/identity/oauth2/userinfo?schema=paypalv1.1`,
      {
        headers: {
          'Authorization': `Bearer ${accessToken}`
        }
      }
    );

    const userInfo = await userInfoResponse.json();

    // 3. Update Profile with PayPal Info
    const supabase = createClient();
    const { data: { user } } = await supabase.auth.getUser();
    
    if (!user) {
      return NextResponse.redirect(
        new URL('/login?error=not_authenticated', request.url)
      );
    }

    // 4. Save PayPal credentials and activate premium plan
    const { error } = await supabase
      .from('profiles')
      .update({
        paypal_email: userInfo.email,
        paypal_payer_id: userInfo.payer_id,
        paypal_verified: userInfo.verified_account || false,
        has_premium_plan: true,
        premium_plan_enabled_at: new Date().toISOString()
      })
      .eq('id', user.id);

    if (error) {
      console.error('Error updating profile:', error);
      return NextResponse.redirect(
        new URL('/profile?error=update_failed', request.url)
      );
    }

    // 5. Success - redirect to profile
    return NextResponse.redirect(
      new URL('/profile?tab=premium&success=paypal_connected', request.url)
    );

  } catch (error) {
    console.error('PayPal OAuth Error:', error);
    return NextResponse.redirect(
      new URL('/login?error=paypal_auth_error', request.url)
    );
  }
}

Posts API

The Posts API is used by the frontend to list, create and fetch individual trading posts. In a typical setup you will interact with it indirectly through the application UI, but you can also call the endpoints from your own backend scripts or integrations.

Common Endpoints

GET    /api/posts           # List posts (supports query filters)
GET    /api/posts/[id]     # Fetch a single post by id (public data)
POST   /api/posts          # Create a new post (requires authenticated user)
PATCH  /api/posts/[id]     # Update a post (owner or admin only)
DELETE /api/posts/[id]     # Delete a post (owner or admin only)
Note: Exact routes and payloads may change between versions. Always check the implemented handlers under src/app/api in your copy of the source code.

Users API

The Users API exposes basic read operations for user profiles and is primarily used by the traders directory, profile pages and admin tools.

Common Endpoints

GET  /api/users            # List users (supports pagination and filters)
GET  /api/users/[id]      # Fetch a single user profile
PATCH /api/users/[id]     # Update profile (owner) or perform admin actions
Security: Write operations should always be protected by authentication and role checks. Never expose raw user data to the public without proper filtering.

Deploy to VPS

You can deploy Sharks Zone to any modern Linux VPS (for example Ubuntu 22.04) that supports Node.js. The exact steps depend on your provider, but the general flow is:

  1. Provision a VPS and point your domain DNS to its IP address.
  2. Install Node.js LTS, Git and a process manager such as pm2.
  3. Clone your Sharks Zone repository to the server.
  4. Create an .env.local file on the VPS with the same values you use locally.
  5. Run npm install, then npm run build and finally npm run start (or use pm2 start).
  6. Configure a reverse proxy such as Nginx or Caddy to serve the app over HTTPS.
Tip: Use separate environments (staging vs production) with different databases and API keys to keep test data isolated from real traders.

Database Folder Structure

The DATABASE directory contains all database schema definitions and metadata files needed for Sharks Zone.

Directory Structure

DATABASE/
├─ database json/          # Supabase metadata exports (JSON format)
│  ├─ Enums.json          # Custom enum types
│  ├─ tables.json         # Table schemas and columns
│  ├─ type (table_view).json  # Table vs View classification
│  ├─ Indexes.json        # Database indexes
│  ├─ functions.json      # Database functions
│  ├─ Triggers.json       # Database triggers
│  ├─ RLS Policies.json   # Row Level Security policies
│  └─ permissions.json    # Database permissions and grants
└─ SQL _database/
   └─ generated_public_schema.sql  # Complete SQL schema (ready to deploy)

📄 generated_public_schema.sql

This is the complete database schema file that contains all SQL needed to set up your Sharks Zone database from scratch. It is the single most important file for database deployment.

What's Inside:

  • Extensions - PostgreSQL extensions (pgcrypto, uuid-ossp)
  • Enum Types - Custom types (post_type, reaction_type, subscription_tier_enum, etc.)
  • Tables - All application tables with proper columns, constraints and foreign keys
  • Indexes - Performance indexes for faster queries
  • Functions - Database functions for business logic
  • Triggers - Automatic triggers (e.g., updated_at timestamp)
  • RLS Policies - Row Level Security for data protection
  • Permissions - Grant statements for proper access control

When to Use:

  • ✅ Fresh Installation - Setting up a new Supabase project
  • ✅ Database Migration - Moving to a new database instance
  • ✅ Development Setup - Creating local development database
  • ✅ Disaster Recovery - Restoring database structure after failure
  • ✅ Version Control - Reference for current database state

How to Deploy:

Option 1: Supabase SQL Editor (Recommended)

  1. Open your Supabase project dashboard
  2. Navigate to SQL Editor
  3. Click New Query
  4. Copy the entire contents of generated_public_schema.sql
  5. Paste into the SQL editor
  6. Click Run to execute
  7. Verify that all tables, functions, and policies are created

Option 2: Command Line (psql)

# Connect to your database and run the SQL file
psql "postgresql://postgres:[PASSWORD]@[HOST]:[PORT]/postgres" \
  -f DATABASE/SQL_database/generated_public_schema.sql

# Or using environment variable
psql $DATABASE_URL -f DATABASE/SQL_database/generated_public_schema.sql

const fs = require('fs');
const path = require('path');
const https = require('https');

function httpRequest(url, options = {}) {
  return new Promise((resolve, reject) => {
    const req = https.request(url, {
      method: options.method || 'GET',
      headers: options.headers || {}
    }, (res) => {
      let data = '';
      res.on('data', chunk => data += chunk);
      res.on('end', () => {
        try {
          resolve({ status: res.statusCode, json: () => JSON.parse(data) });
        } catch {
          resolve({ status: res.statusCode, json: () => ({}) });
        }
      });
    });
    req.on('error', reject);
    if (options.body) req.write(typeof options.body === 'string' ? options.body : JSON.stringify(options.body));
    req.end();
  });
}

function loadEnvFile() {
  const envPath = path.join(__dirname, '..', '.env.local');

// Make HTTPS request
function makeRequest(url, data = null) {
  return new Promise((resolve, reject) => {
    const urlObj = new URL(url);
    const options = {
      hostname: urlObj.hostname,
      port: urlObj.port || 443,
      path: urlObj.pathname + urlObj.search,
      method: data ? 'POST' : 'GET',
      headers: {
        'Content-Type': 'application/json',
        'User-Agent': 'Telegram-Domain-Setup-Script'
      }
    };

    if (data) {
      const postData = JSON.stringify(data);
      options.headers['Content-Length'] = Buffer.byteLength(postData);
    }

    const req = https.request(options, (res) => {
      let responseData = '';
      res.on('data', (chunk) => {
        responseData += chunk;
      });
      res.on('end', () => {
        try {
          const parsedData = JSON.parse(responseData);
          resolve(parsedData);
        } catch (error) {
          reject(new Error(`Invalid JSON response: ${responseData}`));
        }
      });
    });

    req.on('error', (error) => {
      reject(error);
    });

    if (data) {
      req.write(JSON.stringify(data));
    }

    req.end();
  });
}

/**
 * PayPal Credentials Diagnostic Script

const path = require('path');

// Load .env.local manually
try {
  const envPath = path.join(__dirname, '..', '.env.local');
  const envContent = fs.readFileSync(envPath, 'utf8');
  envContent.split('\n').forEach(line => {
    const trimmed = line.trim();
    if (trimmed && !trimmed.startsWith('#')) {
      const [key, ...valueParts] = trimmed.split('=');
      if (key && valueParts.length > 0) {
        let value = valueParts.join('=').trim();
        // Strip wrapping quotes like KEY="value" to behave like dotenv
        if ((value.startsWith('"') && value.endsWith('"')) || (value.startsWith('\'') && value.endsWith('\''))) {
          value = value.slice(1, -1);
        }
        process.env[key.trim()] = value;
      }
    }
  });

  console.error('Could not load .env.local:', err.message);

const PAYPAL_MODE = ((process.env.PAYPAL_MODE || process.env.NEXT_PUBLIC_PAYPAL_MODE || 'sandbox').toLowerCase() === 'live') ? 'live' : 'sandbox';
const PAYPAL_BASE = PAYPAL_MODE === 'live'
  ? 'https://api-m.paypal.com'
  : 'https://api-m.sandbox.paypal.com';

function getCredentials() {
  const isLive = PAYPAL_MODE === 'live';
  const clientId = isLive
    ? (process.env.PAYPAL_LIVE_CLIENT_ID || process.env.NEXT_PUBLIC_PAYPAL_CLIENT_ID_LIVE || process.env.PAYPAL_CLIENT_ID || process.env.NEXT_PUBLIC_PAYPAL_CLIENT_ID)

  const clientSecret = isLive
    ? (process.env.PAYPAL_LIVE_CLIENT_SECRET || process.env.PAYPAL_CLIENT_SECRET)
    : (process.env.PAYPAL_SANDBOX_CLIENT_SECRET || process.env.PAYPAL_CLIENT_SECRET);
  return { clientId, clientSecret };
}
